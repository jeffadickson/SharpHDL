## Priorities after the verified simulator baseline

Preserve the passing correctness gates while expanding representative workloads and reducing state/RAM boundary overhead. Complete issue #24's actual Core/HLS/Simulation extraction without duplicating hardware semantics. Continue hardware-aware debugging and full-system usability; source breakpoints are not the leading priority. Four-state simulation and general gate-level equivalence remain separate workstreams rather than being implied by the two-state JIT milestone.

## Review policy

Keep PAR identifiers stable. Update execution status from actual logs and artifacts, with the tested commit, workload, toolchain and remaining limitations. Retain the distinction between historical unverified implementation entries and current executed evidence. Performance must use matched work, visibility and timing scope; no cross-project superiority claim from unlike CPU examples.

## Review — 2026-10-19

Upstream `skryl/rhdl` master remains at [8dc7579](https://github.com/skryl/rhdl/commit/8dc75799ba4e02045237760c3cd95827f14db387) (2026-03-03). Its README and web simulator documentation have the same blob SHAs as the prior review (`126d5795`, `1171ef92`). There are **no new upstream commits** since the previous audit. The previously documented upstream CIRCT/Arcilator RISC-V modes, Linux/BusyBox runner, and Electrobun desktop packaging remain meaningful comparison targets; see [RISC-V](https://github.com/skryl/rhdl/blob/master/docs/riscv.md) and [web](https://github.com/skryl/rhdl/blob/master/docs/web_simulator.md).

The 2/4/8/16-tap replays succeeded with Icarus in the [2026-10-16 CI run](https://github.com/jeffadickson/SharpHDL/actions/runs/38845913306), which also passed Linux/Windows unit tests and Core RTL/Verilator jobs. Commits: [planner](https://github.com/jeffadickson/SharpHDL/commit/316b1a41705870eb21ec9cac2d8a6d51804caa82), [emitter](https://github.com/jeffadickson/SharpHDL/commit/22b3c791067fc7254e67a0709f097f8c5de84d54), [multiplier sharing](https://github.com/jeffadickson/SharpHDL/commit/96b5f56c3854fa041a052873e37b0d1f7080051e), [CI gate](https://github.com/jeffadickson/SharpHDL/commit/c016969b191505cb1ac71d40e98bc0164f9a6967). ## Review — 2026-10-26

- **Upstream:** `skryl/rhdl` `master` remains [`8dc7579`](https://github.com/skryl/rhdl/commit/8dc75799ba4e02045237760c3cd95827f14db387), the same commit reviewed on October 19. No new upstream commits or newly introduced capabilities were found. Prior CIRCT/Arcilator, Linux/BusyBox RISC-V and Electrobun references are *existing* capabilities, not new releases.
- **SharpHDL:** `main` advanced exactly one commit since [`19cb109`](https://github.com/jeffadickson/SharpHDL/commit/19cb109f22728cfe35ba85501877b493c841969a): [`90346c3` — scheduled-machine lowering](https://github.com/jeffadickson/SharpHDL/commit/90346c36a2ae831a08876189578373fd3c745d69) (committed October 20 UTC). This adds algorithm-neutral `ScheduledMachineBuilder` under `SharpHDL.HLS`, directly lowering finite states, guards, register transfers, single-port RAM access and resource declarations to canonical Core IR; the FIR compiler now uses it instead of a legacy `Module`. The FIR *planner* remains specialized and supports controller emission for 2..16 taps. The separate planner's broader 1..256-tap range is not evidence that the compiler handles those tap counts.
- **Verification:** [October 21 xUnit workflow `39613566197`](https://github.com/jeffadickson/SharpHDL/actions/runs/39613566197) completed with **10/10 successful jobs** including Linux/Windows unit, Core-layering, scheduled FIR RTL/Icarus replay at 2/4/8/16 taps, and Core/Verilator checks. [Compiled simulator workflow `39613566312`](https://github.com/jeffadickson/SharpHDL/actions/runs/39613566312) and [learner browser `39613566434`](https://github.com/jeffadickson/SharpHDL/actions/runs/39613566434) also succeeded at that source commit. Results are CI observations; no local re-execution was performed in this review.
- **Parity movement:** PAR-003 (scoped state/RAM control), PAR-006 (Core IR simulation/RTL pipeline), PAR-020 (general reusable *lowering*, not general automatic HLS scheduling) and PAR-024 (latest-commit CI coverage) move forward. The new layer does not close #6/#24/#26 or the documented four-state, gate-level, portable browser, multi-resource, physical DSP/BRAM and target timing gaps. Existing [#6](https://github.com/jeffadickson/SharpHDL/issues/6), [#24](https://github.com/jeffadickson/SharpHDL/issues/24), [#26](https://github.com/jeffadickson/SharpHDL/issues/26) remain ownership; no duplicate issue was created.
