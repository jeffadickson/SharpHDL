Give the drill four ticks

Start the drill, then complete four practice ticks. Turning Practice enabled off holds the count on clock edges while Running. Stop cancels the drill. The state changes only on a clock edge.

No matching transition means “stay here.” Stop wins over finishing when both happen together. Reset returns to Ready and clears the count; it leaves input checkboxes unchanged. For a fresh drill, turn Stop off before starting.

Slide the bits, keep the binary point
Our signed number has eight total bits and four fractional bits. One tiny step is 1/16. Its range is −8 to +7.9375. Shifting changes the value; the binary point stays in the same place.
Read the bit pattern as a signed integer, then divide by 16.
Left shift · wrap
Same width; high bits can be lost.
Right shift · floor
Discarded fractions round downward.
Right shift · nearest even
Halfway picks an even raw integer.
Try −0.1875, shift 1: the exact half is −0.09375. It falls between representable steps. Floor and nearest-even both give −0.125. Try +0.1875 next: floor gives +0.0625; nearest-even gives +0.125.
var x = new SFixed<W8,F4>(input);
var doubled = x << 1;
var halved = x >> 1; // Arithmetic shift; floor
var rounded = x.ShiftRight(1, Rounding.NearestEven);

What is actually being simulated?
This page evaluates the actual SharpHDL expression graphs exported with these examples. A small JavaScript engine uses exact-width BigInt arithmetic and simultaneous register updates. It works offline, with no account or network calls.
The offline graph engine is not a Verilog parser. The accompanying generated Verilog was separately checked with Icarus against independent reference results. The browser engine is checked against the same expected traces. This demonstrates the tested graphs; it does not prove arbitrary RTL equivalence.
