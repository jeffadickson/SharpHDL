Slide the bits, keep the binary point
Our signed number has eight total bits and four fractional bits. One tiny step is 1/16. Its range is −8 to +7.9375. Shifting changes the value; the binary point stays in the same place.

Language coverage and requirements
SharpHDL 0.13 has structural, combinational CIL and explicit sequential CIL interfaces. The structural library executes C#/F#/VB on the host to construct a graph; the behavioral frontend decodes selected CIL methods into combinational graphs or clocked operation state machines. A construct available during host execution does not necessarily translate inside a behavioral method. This matrix describes the current implementation, not all constructs the source languages can express.

Why a clocked loop needs an explicit mode
`for(i=0;i<12;i++) sum+=data` can mean twelve chained adders, one adder reused for twelve cycles, or a pipeline accepting a new item each cycle. Syntax alone cannot choose the architecture. The frontend offers combinational unrolling and explicit BuildSequential with an execution-edge budget. It must never silently turn a combinational function into a variable-latency transaction. Runtime while loops also need a way to keep the engine responsive and explain what happens if they never terminate.
A state machine today
var fsm = new StateMachine(m, "drill", "Ready", "Running", "Done");
fsm.When("Ready", start, "Running")
   .When("Running", stop, "Ready")       // First match wins.
   .When("Running", finished, "Done")
   .When("Done", acknowledge, "Ready");
fsm.Build();
m.Drive(running, fsm.Is("Running"));

The helper generates the state register and next-state muxes. Data registers remain explicit so all assignments observe pre-edge state. Names are annotations; the first state is reset, the minimum binary width is selected, and an unused encoding recovers on the next edge. BuildSequential separately extracts a state machine from supported CIL, including runtime while loops. Unused-encoding recovery cannot detect a bit upset that lands in another valid state.
Fixed-point shift contract
For signed `SFixed<W,F>`, real value = signed(raw)/2^F. `x << n` keeps W and F, scales by 2^n and wraps; `x >> n` keeps W and F, scales by 2^-n and rounds down to the format grid. This differs from signed integer division's toward-zero rule. `x.ShiftRight(n, Rounding.NearestEven)` is explicit rounded scaling. Constant counts from 0 through W are accepted; negative or larger counts are rejected rather than using C# integer count masking. At n=W, left produces zero, floor right produces raw zero or minus one, and nearest-even produces zero. Operators do not change the binary-point position. Use Convert to change format.
Workbook use and simulation honesty
The HTML companion is useful after the register/clock lesson: ask a child to predict, advance one edge, and explain a mismatch. The hockey drill exposes states, pause, reset and a four-bit count. The fixed-point and loop panels are optional extensions; no testbench syntax is required from the child. Adult-owned verification remains essential even when the student interface hides it.
The offline engine evaluates exported Expr graphs using JavaScript BigInt. “Open in VeriSim” launches the generated Verilog and a compact teacher-owned testbench in https://senolgulgonul.github.io/verisim/. VeriSim uses Icarus compiled to WebAssembly. Its initial hosted load needs network access. Links use its documented #d=...&t=... base64url format. The payloads pass local Icarus; the hosted UI has not been exercised in this environment. The offline graph engine is separate.
