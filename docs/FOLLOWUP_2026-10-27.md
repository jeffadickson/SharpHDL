## Reproduction and boundaries

Check the checkout and output parent directories exist before running commands.
From the root, run the saved coverage settings with dotnet test, the standalone
runner from an isolated working directory, `bash tools/run-scheduled-rtl.sh`,
`bash tools/run-scheduled-fuzz.sh 60`, saved Stryker configs in the unit-test
directory, and `yosys -s tools/qualify-scheduled-memory.ys` after generating the
suite into generated/scheduled-suite. The local scripts retain native output paths
and fail on simulator errors or saved fuzz crashes. Raw artifacts stay local.

The stateful CIL path is an explicit documented subset: static UInt32 return,
Int32/UInt32/Boolean values, unchecked arithmetic/bitwise/comparisons, branch,
switch, runtime loops and one uint[] memory. Calls, checked arithmetic, division,
shifts, packed/narrow ports, exception handlers and legacy vendor MemoryOptions
are rejected. Exact InitialMemory is supported. Method/IL provenance is present;
full source-line mapping for every scheduled state remains future work.

Resources are combinational one-edge bindings, not iterative multiplier latency
models. Dynamic cross-kernel resource arbitration, automatic bank partitioning,
true multiport memories, multiclock Core, global schedule optimization, formal
proof and physical FPGA qualification remain outside this implemented slice.
Independent-machine isolation tests must not be described as a shared-resource
multi-kernel scheduler. SCHED-011 remains partial pending that broader scope.
